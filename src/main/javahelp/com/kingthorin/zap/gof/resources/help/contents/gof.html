Good Old Files

An active scan rule that probes for backup, editor-swap, old-version, and copy variants of files discovered during scanning.

Overview

The Good Old Files (GOF) rule attempts to find exposed backup copies, old versions, and editor temporary files by probing for common filename variants at discovered paths. For example, if ZAP discovers index.php , GOF will probe for variants using nine permutation strategies:

  • index.php.bak, index.php.backup (extension append)
  • index.bak, index.backup (extension replace)
  • index.asp, index.aspx (extension switch)
  • index_old.php, index.old.php (extension combination)
  • index - Copy.php, index_old.php (filename suffix)
  • Copy of index.php, old_index.php (filename prefix)
  • index0.php, index2.php (digit enumeration)
  • Directory variants like /admin_old/, /backup/

How It Works

The rule:

  1. Runs as an optional active scan rule (disabled by default)
  2. Processes each discovered file/directory node in the site tree
  3. Generates candidate filenames using configurable permutation strategies
  4. Probes each candidate and records those that exist
  5. Uses ZAP's soft-404 detection (Custom Pages + Analyser) to avoid false positives

Enabling GOF

GOF ships disabled by default. Enable it via:

  • Context Menu: Right-click a site node, select "Attack" → "Attack with Good Old Files"
  • Policy Manager: Edit a scan policy, set GOF threshold to Medium or higher
  • API/Automation Framework: Use standard active scan endpoints with GOF rule ID

Configuration

Configure GOF defaults under Tools → Options → Good Old Files:

  • Enable/disable each of the nine permutation strategies
  • Add custom filename patterns to default wordlists
  • Set default attack strength for candidate generation

When invoking GOF via the context menu, a dialog allows choosing the attack strength for that invocation only, without changing the saved default. Strategy selection and custom wordlists always use the values configured under Options; they cannot be overridden per invocation, since the underlying active scan engine only propagates attack strength to the running scan.

Attack Strength

Attack strength controls how many candidate files are generated per discovered node:

  • LOW (~15 candidates): Quick check with most common file variants; suitable for large sites
  • MEDIUM (~35 candidates): Balanced coverage; all strategies get partial representation
  • HIGH (~75 candidates): Thorough scan with most wordlist entries
  • INSANE (unlimited): Generate all possible candidates from all enabled strategies

Alert Levels

  • Medium/Medium: Backup file found (200 response + confirmed not 404)
  • Low/Low (threshold=LOW): Variant exists but access restricted (401/403)
